# Video Manager — авто качество видео

Браузерное расширение (Manifest V3) для браузеров на движке Chromium.
Автоматически выбирает лучшее качество видео на HDRezka и её зеркалах, чтобы не переключать разрешение вручную.

## Скачать и установить (для пользователей)

1. Откройте страницу репозитория: `https://github.com/YambarshevViktor/video-manager`
2. Нажмите зелёную кнопку **Code → Download ZIP** и распакуйте архив в любую папку.
3. Откройте страницу управления расширениями вашего браузера.
4. Включите **Developer mode / Режим разработчика** (переключатель справа вверху).
5. Нажмите **Load unpacked / Загрузить распакованное расширение** и выберите распакованную папку.
6. Закрепите иконку Video Manager на панели, откройте любое видео на HDRezka — бейдж появится по центру сверху плеера.

Обновление: скачайте свежий ZIP, замените им старую папку и нажмите «обновить» (⟳) на карточке расширения, затем жёстко перезагрузите вкладку с видео.

## Режимы

| Режим | Поведение |
|---|---|
| **Умный** | Старт с уровня под размер плеера и сеть → шаг вниз при буферизации → возврат вверх после ~30 с стабильности |
| **Максимум** (по умолчанию) | Всегда высший доступный уровень. Без автоснижения — может буферить на слабом интернете |
| **Ручной потолок** | Всегда высший уровень, но не выше выбранного (360p … 1080p Ultra … 4K). Без адаптации |

Размер окна учитывается **только в умном режиме** (высота плеера × DPR; в фуллскрине — экран).
Лестница — по рангу уровня, поэтому `1080p Ultra` — отдельный шаг выше обычного `1080p`.

## Как это работает

- **HDRezka и зеркала — основной путь**: DOM-адаптер находит пункты меню качества `360p … 1080p Ultra … 4K` и кликает нужный. Переключение там перезагружает поток (лоадер 1–2 с) — это поведение самого сайта. Поэтому умный режим консервативный: выбирает один раз на старте, вниз — только после повторных буферизаций, вверх в рамках сессии не идёт.
- **Плееры hls.js / dash.js / shaka / video.js (VHS)** — перехват инстанса плеера в MAIN-мире на `document_start` (где MAIN-мир отвечает), прямое управление уровнем, сайт не может «перетереть» выбор (энфорс каждые 15 с).
- **Где не выйдет**: уровни, которые сайт не отдаёт без премиума (например, `1080p Ultra / 4K`), DRM. Бейдж покажет `•••`, диагностика — причину.
- **Где работает**: только HDRezka и её зеркала из списка в настройках. На других сайтах расширение не внедряется.

Бейдж поверх плеера: текущий уровень и текущая (живая) скорость (`720p · 1×`) + цвет режима (зелёный — Макс, синий — Умный,
серый — Ручной; «Поиск…» — уровни пока не найдены). Наведи курсор — увидишь режим в подсказке. Клик — мини-панель (режим, потолок,
уровни, скорость, скрыть). Бейдж можно
таскать мышью в любое место (позиция запоминается на домен, сброс — в мини-панели).
Скрытие клавишей `V` (настраивается) действует только на текущей странице: открыл/перезагрузил страницу — значок снова на месте. Живёт до перезапуска браузера.
В фуллскрине бейдж переносится внутрь.

## Скорость видео

Скорость ставится **напрямую на `video.playbackRate`** — меню плеера не трогаем, поэтому она не зависит от MAIN-мира / CSP. Выбор запоминается между сессиями,
сброс скорости сайтом автоматически возвращается (fightback); явный сброс в 1.0
тоже доводится до видео — залипшей скорости больше нет.

Управление: мини-панель бейджа (− / значение-сброс-возврат / + и пресеты), попап, горячие
клавиши на странице с видео — `S` медленнее, `D` быстрее, `R` сброс к 1.0 / возврат к скорости до сброса,
`G` переключение с избранной (по умолчанию 2). Работают и в русской раскладке,
в полях ввода не срабатывают, отключаются в настройках. Шаг и избранная — в настройках.

## Проверка на rezka.ag

1. Откройте любое видео, подождите 5–10 с.
2. Бейдж должен показать высшее доступное качество.
3. Клик по бейджу → список уровней с сайта (360 … 1080 Ultra … 4K) → клик по уровню переключает.
4. Настройки → «Диагностика вкладки» → «Обновить»: видно `players`, `levels`, `current`, события.

## Настройки

- Попап (иконка расширения): вкл/выкл, режим, потолок, скорость, вкл/выкл для текущего сайта, статус вкладки + раскрывающаяся таблица «Инфо» — всё, что отдаёт элемент, простым языком и каждая мелочь с новой строки: состояние и перемотка, время и % просмотра, качество и режим, скорость, звук и все аудиодорожки, субтитры (статус, фразы), видеодорожки, картинка, кадры (показано/пропущено/битые), буфер и сеть, источник и его тип, вес (по качествам: повтор запроса плеера + размер каждого файла; иначе размер файла или куски HLS и что подгружено), по факту (реальный кадр и сходимость с выбранным; тизер и занижение подсвечиваются), автозапуск, повтор, кнопки, защита, ошибки. Та же информация — кнопкой «Инфо на видео» в мини-панели: полупрозрачная плашка в левом верхнем углу поверх видео, обновляется сама, закрывается крестиком.
- Страница настроек: всё то же + размер плеера, хоткей, скорость (шаг, избранная, вкл/выкл клавиш S/D/R/G), зеркала HDRezka, диагностика, экспорт/импорт JSON.
- Зеркала: `rezka.ag` уже в списке по умолчанию (матчит и поддомены), новые зеркала добавляются тем же полем.

## Дата добавления («Добавлено» в Инфо)

Строка «Добавлено» в таблице Инфо (попап и плашка на видео) показывает, когда серия/фильм
появились на сайте: `1 ноября 2024 — 2 сезон 3 серия (ColdFilm)`. Перезаливы — отдельными
строками (`— перезалив`), «сериал завершён» — строкой уровня тайтла.

Как это работает:

- `scripts/collect_updates.py` — сборщик (только стандартная библиотека). Раз в день качает
  главную, парсит блок «Горячие обновления сериалов и фильмов» (дата + тайтл + сезон/серия +
  озвучка как есть) и дописывает записи в `data/updates.json`. Ключ: числовой id из адреса +
  сезон + серия + озвучка (нормированная); у фильмов сезона/серии нет; «завершён» — ключ уровня
  тайтла; перезалив в тот же день — отдельная запись. Дедуп по (ключ + дата + перезалив),
  повторный прогон ничего не дублирует. Дополнительно тянем title/url/type/year —
  для сверки (`--dump`); качество и рейтинг осознанно не храним (скачут и врут в истории).
- `.github/workflows/updates-collect.yml` — cron раз в день + ручной запуск (Actions → Run workflow):
  - `mode=live` — скачать главную сейчас (как cron, но вручную);
  - `mode=day` + `date=2010-06-15` — **один день** из веб-архива (для первой проверки);
    с `dry_run=true` файл не меняется, в логе видно, что нашлось;
  - `mode=range` + `date_from=2010-01-01` + `date_to=2011-01-01` — **диапазон** из архива
    (снапшоты ~1 в неделю, окно каждого ~3 дня; диапазон больше года разбейте на части).
- Бэкфилл 2010→2011: запустите `range` по частям (напр. поквартально) с `dry_run=true`,
  проверьте лог, потом те же запуски без dry_run — коммиты в `data/updates.json` пойдут сами.
- Расширение тянет `data/updates.json` из этого же репозитория
  (`raw.githubusercontent`, кэш 24 ч), ищет точное
  совпадение (id + сезон + серия + озвучка), иначе «залито целиком», иначе «неизвестно».
  Свой источник задаётся через `updatesUrl` в storage.

## Ограничения (честно)

- Переключение качества на сайтах с меню = перезагрузка потока сайтом (короткий лоадер) — не баг расширения.
- `1080p Ultra / 2K / 4K` на rezka могут требовать премиум — расширение берёт то, что отдаёт меню плеера, обхода нет.
- Хоткей `V` может конфликтовать с клавишами сайта — смените его в настройках.
- Safari и Firefox не поддерживаются.
- Yab (WebKit): расширение работает, но ускорение выше 2× не применяется — ограничение медиа-движка WebKit.

## Файлы проекта

```
manifest.json          манифест MV3
background.js          service worker: дефолты, кэш диагностики
injected_main.js       MAIN-мир: перехват плееров, ABR-контроллер
content_isolated.js    бейдж, DOM-адаптер, хоткей, диагностика, строка «Добавлено»
popup.html/js/css      попап
options.html/js/css    настройки
icons/                 иконки (заглушка, замените своими)
scripts/collect_updates.py  сборщик истории заливок → data/updates.json
.github/workflows/updates-collect.yml  cron + ручной прогон (день/диапазон)
data/updates.json      история «Добавлено» (тянется с raw.githubusercontent)
```

Локализация: интерфейс на русском, все строки в UI-файлах, структура готова под `chrome.i18n` + EN вторым файлом.
