# AGENTS.md — Video Manager (как всё устроено)

> Читать перед любыми правками. Проект: MV3-расширение, авто-качество видео.
> Язык UI: русский. Главный приоритет: rezka.ag и зеркала (CDN-плеер на `<pjsdiv>`).

## Статус (окт 2026)

- Автопереключение через DOM-меню на rezka/зеркалах — **работает** (v0.1.10+).
- Перехват плееров через MAIN-мир (`world: "MAIN"`) в Dia **не подтвержден**:
  `mainAlive=false` в диагностике = MAIN-скрипт не отвечает (старый Chromium без
  `world:MAIN`, либо CSP режет fallback-инжект). Поэтому DOM-адаптер — основной путь.
- Scope: только rezka.ag и зеркала из списка (v0.1.60+). Вне rezka скрипты не внедряются, поэтому YouTube/DRM/Netflix/Okko/Кинопоиск — не поддерживаются в принципе.

## Ключевые решения (не ломать)

1. **Лестница по рангу, не по высоте.** `1080p Ultra` — отдельный шаг (3.5) выше `1080p` (3).
   Ранги: 360:0, 480:1, 720:2, 1080:3, 1080U:3.5, 2K:4, 4K:5. Кап `1081` = Ultra.
2. **Режимы строго раздельные.** `max` = высший доступный всегда (потолок и окно
   игнорируются).
   `manual` = высший в пределах потолка, без адаптации. `smart` =
   единственный адаптивный (старт по окну/сети, вниз при stall, вверх после стабильности).
   Размер окна (`sizeCapRank`, высота×DPR) учитывается **только в smart**.
3. **MAIN и isolated — разные JS-миры.** Флаги через `window.*` между ними НЕ видны,
   только `window.postMessage` (`vm-cmd` → MAIN, `vm-main` → isolated).
4. **Версии в 3 местах** (обновлять вместе): `manifest.json`, `VM_VERSION` в
   `content_isolated.js`, строка «должна быть X» в `options.js`.
5. **Скрытие бейджа — в пределах текущей страницы.** Живёт в `chrome.storage.local.badgeHiddenTabs`
   (`{tabId: true}`), сбрасывается в `onStartup`, записи мёртвых вкладок чистит
   `tabs.onRemoved`. Топ-фрейм при каждой загрузке страницы удаляет запись своей
   вкладки — скрыл на одном видео, открыл другое (даже в той же вкладке), и значок
   снова на месте, если включена `badgeDefaultVisible`. Перезагрузка рекламного
   iframe сброс не вызывает (только топ-фрейм). id вкладки контент-скрипт узнаёт
   через `vm-tab-id` у background; старый общий флаг `badgeHidden` просто удаляется
   в `loadSettings`. Кнопка «Скрыть сейчас» в options действует на вкладку,
   выбранную в селекторе диагностики; в экспорт не входит.
6. **Хоткей V — единственный показ/скрытие.** Кнопок «Скрыть» нет
   ни в мини-панели, ни в попапе. Матчинг по `event.code` (`KeyV` + fallback
   `key`/`keyCode`) — работает в русской раскладке; guard на `video` в кадре убран —
   флаг повкладочный через storage, слышат все фреймы этой вкладки. `V` всегда показывает бейдж
   **закрытым** (`closeAllPanels`), отключается чекбоксом `closePanelOnShow` в настройках.
7. **Скорость — только напрямую на `video.playbackRate`, меню плеера
   не трогаем.** Движок в isolated-мире (`applySpeed`/`watchSpeed`/`setSpeed`):
   video-элемент общий для обоих миров, MAIN не нужен — работает на generic/mp4
   и под CSP. Диапазон 0.07–16, шаг `speedStep` (дефолт 0.5), избранная
   `preferredSpeed` (дефолт 2). Явный выбор пользователя (`setSpeed`, смена `speed`
   в storage — включая сброс в 1.0) доводится до видео принудительно (`force=true`,
   `speedTouched`). Иначе fightback: `ratechange`/`loadedmetadata`/`play` + тики
   возвращают выбранное нетронутым видео — только пока выбрано ≠ 1.0; наши
   (тронутые) доводим всегда (анти-зацикливание 400мс через `speedApplyAt`). Хоткеи S/D/R/G — по `event.code` (RU-раскладка ок),
   только при `video|audio` на странице, игнор в полях ввода, toggle `speedHotkeys`.
   `R` — переключатель `toggleResetSpeed` (1.0 ↔ `lastSpeedBeforeReset`, общее для фреймов через storage).
   `×` — знак умножения (не латинская x) везде в подписях скорости; при скорости > 1.0
   наклонным (italic) делается только значение скорости в бейдже (отдельный span) —
   остальной бейдж, панель, попап и оверлей прямые; замедление (< 1.0) тоже прямое
   (обратного италика в CSS нет). Пропущенное из-за 400мс-троттлинга применение
   не теряется: `queueSpeedRetry` дотягивает его через ~420мс (поэтому быстрые
   нажатия S/D не «съедаются»).
   V занята бейджем. Бейдж всегда показывает живую скорость: `720p · 1×`.
   Хранилище: `speed, speedStep, preferredSpeed, speedHotkeys, lastSpeedBeforeReset` (экспорт/импорт в options — кроме `lastSpeedBeforeReset`).
8. **Внедрение — динамическое, только HDRezka и зеркала.** Static content_scripts
   убран из манифеста: `applyContentScripts()` в background регистрирует оба скрипта
   (MAIN + ISOLATED, document_start, all_frames) через `chrome.scripting` по целям
   `computeTargets()`. Строго allowlist: матчи = `sites` (список зеркал, по умолчанию
   `['rezka.ag']`) + perSite-вкл; perSite-выкл снимает исключение. Пустой список =
   страховка на `rezka.ag`. Старый `siteMode='blacklist'` игнорируется везде
   (`computeTargets`, `siteAllowed`, `allowedOn`); onInstalled мигрирует blacklist →
   allowlist + `['rezka.ag']` (прежний список исключений отбрасывается). Шаблоны
   `rezka.ag`/`*.x` превращаются в `*://h/*` + `*://*.h/*` (голый
   хост `*.h` в Chrome не покрывает!). Перерегистрация — в onInstalled/onStartup и при
   смене siteMode/sites/perSite. Старый Chromium без world в scripting API: fallback —
   оба скрипта в ISOLATED (DOM-качество и скорость работают). Уже открытые вкладки
   подхватывают только после перезагрузки — об этом есть подсказки в popup/options.
   Самопочинка: popup и options при открытии шлют `vm-apply-scripts` (регистрация +
   статус `lastReg`), т.к. onInstalled при ⟳ распакованного расширения срабатывает
   не всегда. Статус виден в начале диагностики options (`ВНЕДРЕНИЕ: ...`).
9. **Потолок не трогает режим.** Клик по потолку в попапе/options меняет только
   `cap` (в max потолок и так игнорируется). Было: попап молча сбрасывал max→manual.

10. **Пассивный режим скорости (>2×): как VSC — только `playbackRate`, плеер не трогаем.**
   Любой клик по меню качества = перезагрузка потока сайтом, на высокой скорости это
   срывает буфер. Поэтому при `desiredSpeed() > 2` (`speedPassive()` в isolated,
   проверка `playbackRate > 2` в MAIN): `domTick`/pjs/gear/открывалки не бегают,
   степ-дауны/степ-апы/энфорс заморожены, пробы веса (`probeStreamMeta/Sizes`,
   `topQsTick`) не качают — качество остаётся как есть. Скорость ставится как обычно,
   явные клики пользователя по уровням (`vm-force`) работают всегда. Это НЕ снижение
   качества (v0.1.39) и НЕ отключение тона — оба отвергнуты, см. память.

## Протокол MAIN ↔ isolated

- `vm-settings` {enabled, mode, cap, considerSize} — isolated → MAIN при старте/изменении.
- `vm-force` {playerId, index} — клик по уровню из мини-панели → MAIN.
- `vm-ping` → MAIN отвечает `vm-state` {players[], videos[], events[], url}.
- Player entry: {id, kind, levels[{label,height,bitrate,rank}], current, target,
  cooldownUntil, stableSince}. Энфорс max/manual — раз в ~15с (сайт перетирает качество).

## DOM-адаптер (главный путь в Dia)

- `parseQLabel`: строгий — голые числа только из `KNOWN_H` (годы «2024» отбрасываются).
- `groupByMenu`: меню = 2+ пункта с разными рангами в одном контейнере (мусор-одиночки отсекаются).
- `findQualityOpener` (порядок важен!): 1) строка «Качество…» с `[fid]` → 2) такая же
  без fid → 3) aria/title → 4) мелкие кнопки ВНЕ `[fid]`-строк. Кликать надо строку,
  а не внутреннюю подпись-значение (у неё `pointer-events:none`).
- Клики — через `mouseClick()` (pointerdown/mousedown/focus/mouseup/click + `.click()`),
  что кликнули — писать в лог через `describeEl()`.
- `pjsTick` (CDN-плеер rezka): пункты `[f2id]="1..7"` = 360p…4K, активный =
  класс `pjs-cdnplayer-active-menu`, заголовок `f2id=0` пропускается. Видимость НЕ
  требуется; применение проверяется переездом active-класса (`pendingRank`, таймаут 9с).
- Цепочка открытия: `[fid]`-строка «Качество» → подменю. Если строк нет в DOM —
  `gearStep()`: перебор видимых иконок-кнопок (svg, 16–70px, без текста, cursor:pointer)
  по одной за ~2.5с, со снапшотом/откатом pause/mute/volume. Найденная шестерёнка
  кэшируется в `ctl.gear`. Синтетический клик НЕ включает fullscreen (нет жеста) — безопасно.
- `domTick` throttle: скан не чаще раза в 3с (`ctl.lastScan`), клик — не чаще раза в 6с,
  авто-кликов не больше 4 (`clicks`), кроме `stallArmed` (откат при буферизации).
  Дисциплина «только при необходимости» (v0.1.42): довёл до цели — `ctl.settled=true`,
  полная проверка с правом клика не чаще раза в 30с (`ctl.lastFull`); вслепую
  (активное качество не прочиталось) — максимум 1 заходный клик (`ctl.blindClicks`),
  дальше ждём читаемого состояния или force; открывалка — не чаще раза в 30с.
  MAIN-тик — раз в 5с (был 1.5с), энфорс max/manual — раз в 15с (был 4с),
  степ-даун в smart — только со второго подряд подтверждения (~10с буферизации),
  степ-ап — после 90с стабильности (был 30с).

## Shadow DOM

Поиск пунктов идёт через `scanRoots()`/`deepQueryAll()` (документ + открытые shadowRoot,
кэш корней 10с). Счётчики в `recon`: `shadowHosts`, `shadowF2id`, `gearBtns`,
`settingsOpen`, `fidQualityVisible`.

## Диагностика (как читать)

- Options → селектор вкладки → «Обновить». `ПРЯМАЯ СВЯЗЬ` = ответ топ-фрейма
  (пустые фреймы отвечают с задержкой 500мс, чтобы первым был фрейм с видео).
- Каждое «Обновить» = свежий форсированный скан + репорт в кэш (кэш смотрит ту же вкладку).
- `уровни:` — что нашёл скан; `текУровень` — ранг активного; `открывалка` — когда жали кнопку меню;
  `события:` — последние действия (`DOM pjs OK` = победа). Видео-записи несут
  `media{paused,muted,volume,time,dur,buf,rs,ns,frame,loop,drop,played,bufAll,seekN,
  ended,seeking,autoplay,controls,defaultMuted,cors,pitch,sink,drm,err,tracksA,tracksV,tracksT,slen,segs,loaded,qsizes}`
  + `rate` — прямые свойства элемента + `slen/segs/loaded` (вес потока:
  `probeStreamMeta` — один опрос на адрес за сессию: прямой файл — HEAD
  (`Content-Length`), HLS — текст плейлиста (число кусков); `loaded` — байты уже
  скачанных `.ts` по performance-ресурсам) + `qsizes` (вес по качествам:
  `probeStreamSizes` — повтор запроса плеера `get_cdn_series` (пустые поля не шлём,
  как `makeRequest` у Helper'а), расшифровка ссылок `clearTrash`, размер каждого
  `.mp4` (HEAD, запасной GET — как у Helper'а, но `.mp4` принимаем и с query-хвостом);
  если сервер отдал только `.m3u8` — вес каждого качества по HLS-плейлистам
  (`probeHlsSizes`: BANDWIDTH × длительность, без BANDWIDTH — средний сегмент × число кусков);
  селекторы и тип — как у Helper'а (`#simple-seasons-tabs`/episodes `.active`,
  `#translators-list .active`, meta `og:type`); только rezka-подобные страницы; параметры ищет
  и в топ-документе (видео обычно в iframe); обрывы пишет в события как `QS: ...`); строки «Вес» и «По факту» — всегда; попап и оверлей рисуют их простым языком
  (каждая мелочь с новой строки, с большой буквы, без точек и скобок) через
  `mediaRowsPlain` (overlay) и блок «Инфо» попапа.
- Версия скрипта во вкладке < версии пакета → вкладка не перезагружена (старый код!).

## Ограничения (честно)

- Переключение на сайтах с меню = перезагрузка потока сайтом (лоадер 1–2с) — не баг.
- `1080p Ultra/2K/4K` могут требовать премиум — берём то, что отдаёт меню.
- Одиночный `.mp4`, нативный HLS, DRM — «•••»/«Поиск…», в диагностике пусто.
- `world:MAIN` и `chrome.storage.session` требуют свежий Chromium — есть fallback'и
  (script-инжект; память), но в Dia MAIN фактически не отвечает → DOM-путь главный.
